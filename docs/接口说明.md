# 后端接口说明（当前已实现）

> 这份文档只回答一件事：**现在后端有哪些接口、每个接口收什么、还什么、前端怎么用。**
> 接口数量 13 个（12 条路径），全部实测过，示例里的返回值都来自 2026-11-08 / 11-09 的真实运行。

---

## 0. 一句话版本

服务跑在 `http://localhost:8080`，所有接口都在 `/api` 下：

```
上传代码 → 后端自动切片 + 调大模型判定 → 落库
查任务进度 → 看违规明细 → 生成报告（Markdown / HTML）
另外还有一组接口用来管规则库（导入 / 蒸馏 / 统计）
```

---

## 2. 通用约定

| 项 | 约定 |
|---|---|
| 基址 | `http://localhost:8080`（前端 Vite 开发服务器在 5173，靠 `WebConfig` 的 CORS 放开） |
| 编码 | UTF-8；响应 `Content-Type: application/json`（报告的两个导出接口例外） |
| 时间格式 | ISO-8601 本地时间，如 `2026-11-09T13:30:14.089`（**没有时区后缀**，按本机时区理解） |
| 鉴权 | 无。这是单机毕设系统，答辩演示不引入登录 |
| 分页 | 无。数据量小，列表接口用 `limit` 截断 |
| 错误格式 | 统一 JSON（由 `GlobalExceptionHandler` 保证，不会出现 Whitelabel 页） |

错误响应长这样：

```json
{
  "timestamp": "2026-11-09T13:13:02.870856400",
  "status": 400,
  "error": "任务不存在：999"
}
```

| 状态码 | 什么时候出现 |
|---|---|
| 400 | 文件不是 `.java/.py`、上传空文件、taskId 不存在、语言不是 java/python |
| 413 | 文件超过 10MB |
| 500 | 规则库为空、磁盘写失败、调模型失败（`error` 里给中文原因） |

## 3. 接口总览

| # | 方法 | 路径 | 一句话作用 | 会不会调大模型 |
|---|---|---|---|---|
| 1 | GET | `/api/ping` | 探活：服务 + MySQL 是否都通 | 否 |
| 2 | POST | `/api/upload`（别名 `/api/audit`） | 上传代码文件并**同步跑完审计** | **是** |
| 3 | GET | `/api/audit/tasks` | 任务列表（最新在前） | 否 |
| 4 | GET | `/api/audit/tasks/{id}` | 单任务状态 + 违规数 | 否 |
| 5 | GET | `/api/audit/tasks/{id}/findings` | 某任务的违规明细（按行号升序） | 否 |
| 6 | GET | `/api/report/{taskId}` | 报告 JSON（没有就现场生成） | 否 |
| 7 | GET | `/api/report/{taskId}/markdown` | 报告 Markdown 原文 | 否 |
| 8 | GET | `/api/report/{taskId}/html` | 报告 HTML（浏览器直接看） | 否 |
| 9 | POST | `/api/report/{taskId}/regenerate` | 强制重算报告 | 否 |
| 10 | POST | `/api/rules/distill` | 从规范文档蒸馏规则（A 通道） | **是** |
| 11 | POST | `/api/rules/import` | 从 JSON 文件批量导入规则（B 通道） | 否 |
| 12 | GET | `/api/rules` | 规则列表（可按语言过滤） | 否 |
| 13 | GET | `/api/rules/stats` | 规则库统计（按语言/分类/归键） | 否 |

## 4. 逐个接口

### 4.1 探活 `GET /api/ping`

**干什么**：执行一条 `SELECT 1`，一次性证明四件事——Web 起来了、MySQL 在跑、`audit_db` 存在、账号 `audit` 权限有效。

**请求**

```powershell
curl.exe http://localhost:8080/api/ping
```

**响应**

```json
{
  "status": "ok",
  "db": "connected",
  "time": "2026-11-08T19:08:34.826225200"
}
```

**失败边界**：数据库连不上时 `db` 为 `"failed"`，`status` 仍是 `"ok"`（说明 Web 层活着，只是 DB 不通）——这两个字段是分开判断的。

---

### 4.2 上传并审计 `POST /api/upload`

**干什么**：收一个文件 → 识别语言 → 切片 → 按线索挑规则 → 逐块调模型判定 → 写 `finding`。**同步执行**，请求会一直等到审计跑完才返回（BadDemo.java 约 14 秒、3 块）。

**请求**

```powershell
curl.exe -X POST -F "file=@F:\毕业设计\.tmp7\BadDemo.java" http://localhost:8080/api/upload
```

| 参数 | 位置 | 说明 |
|---|---|---|
| `file` | multipart | 必填，只接受 `.java` / `.py`，≤10MB |

**响应**

```json
{
  "taskId": 6,
  "fileName": "BadDemo.java",
  "language": "java",
  "savedAs": "1794202212329_BadDemo.java",
  "detail": "/api/audit/tasks/6 看进度，/api/audit/tasks/6/findings 看结果"
}
```

`taskId` 是后续所有查询的钥匙；`savedAs` 是落盘文件名（加了毫秒时间戳，避免重名覆盖）。

**失败边界**

| 情况 | 返回 |
|---|---|
| 传 `note.txt` | 400 `{"error":"只支持 .java 和 .py 文件，收到：note.txt"}` |
| 空文件 | 400 `{"error":"文件为空"}` |
| 规则库一条都没有 | 500 `{"error":"规则库为空，请先导入或蒸馏规则"}` |

> **前端注意**：因为审计是同步的，`axios` 的 timeout 要设 **≥120000ms**，否则 20 秒左右就断，用户以为失败了。

### 4.4 单任务状态 `GET /api/audit/tasks/{id}`

**干什么**：轮询用。返回任务本身 + 违规条数 + 总判定条数。

```json
{
  "task": { "...": "同 4.3 的单个任务对象" },
  "violations": 3,
  "checked": 3
}
```

- `violations`：真正判为违规的条数（`violated = true`）
- `checked`：本任务落库的判定记录总数

**失败边界**：id 不存在 → 400 `{"error":"任务不存在：999"}`

---

### 4.5 违规明细 `GET /api/audit/tasks/{id}/findings`

**干什么**：报告页按源码顺序展示问题，所以这里已按 `startLine` 升序排好。

```powershell
curl.exe http://localhost:8080/api/audit/tasks/6/findings
```

```json
[
  {
    "id": 7,
    "taskId": 6,
    "ruleId": "JAVA-SB-DMI_CONSTANT_DB_PASSWORD",
    "filePath": "uploads\\1794202212329_BadDemo.java",
    "startLine": 7,
    "endLine": 7,
    "codeSnippet": "    private static final String PASSWORD = \"root@123\";",
    "violated": true,
    "severity": "MEDIUM",
    "reason": "第 7 行以 private static final 常量 PASSWORD 保存明文口令字面量 \"root@123\"……",
    "fixSuggestion": "删除硬编码字面量，改从环境变量或加密配置中心读取……",
    "confidence": 0.55
  },
  {
    "id": 8,
    "ruleId": "JAVA-SB-SQL_NONCONSTANT_STRING_PASSED_TO_EXECUTE",
    "startLine": 11,
    "endLine": 11,
    "codeSnippet": "        return st.execute(\"select * from users where name = '\" + name + \"'\");",
    "severity": "HIGH",
    "reason": "第 11 行将方法参数 name 直接拼接进 SQL 字符串……",
    "confidence": 0.95
  }
]
```

字段用途（前端展示顺序就是它）：

| 字段 | 前端怎么用 |
|---|---|
| `startLine` / `endLine` | 代码高亮的行区间（1-based、含端点） |
| `codeSnippet` | 直接显示在这一行下面，省得前端再去取源码 |
| `severity` | 颜色：HIGH 红 / MEDIUM 橙 / LOW 灰 |
| `confidence` | 显示成百分比（0.95 → 95%），低于 0.5 标"待人工确认" |
| `reason` | 为什么判违规（引用具体行号与变量名） |
| `fixSuggestion` | 修复卡片正文 |

### 4.6 报告 JSON `GET /api/report/{taskId}`

**干什么**：拿一份完整报告。没有就现场生成（生成过程不调大模型，只是统计 + 拼字符串）。

```json
{
  "taskId": 6,
  "complianceRate": 0.987,
  "summaryText": "本次审计共发现 3 处问题，涉及 3 条规则；其中高危 2 处。规则库共 232 条，合规率 98.7%。最需要先修的是第 11 行（JAVA-SB-SQL_NONCONSTANT_STRING_PASSED_TO_EXECUTE）。",
  "markdown": "# 代码审计报告\n\n> 本次审计共发现 3 处问题……",
  "html": "<!doctype html><html lang=\"zh-CN\">……",
  "createdAt": "2026-11-09T13:33:10.221"
}
```

**合规率口径**（论文里要写这一句）：

```
合规率 = 1 − 命中的规则去重数 / 该语言规则总数
```

例如 Java 232 条规则、命中 3 条 → `1 − 3/232 ≈ 0.987`。

**失败边界**：taskId 不存在 → 400。

---

### 4.7 报告 Markdown `GET /api/report/{taskId}/markdown`

`Content-Type: text/markdown;charset=UTF-8`，返回正文（不是 JSON 包装）。前端"下载报告"直接：

```javascript
window.open(`/api/report/${taskId}/markdown`)
```

实测产物见工程里的 `docs/示例报告-BadDemo.md`（41 行，四节：任务信息 / 总体评估 / 问题分布 / 违规明细）。

---

### 4.8 报告 HTML `GET /api/report/{taskId}/html`

`Content-Type: text/html;charset=UTF-8`。浏览器直接打开就是一张排版好的网页，答辩时可以投屏用：

```
http://localhost:8080/api/report/6/html
```

### 4.9 强制重算报告 `POST /api/report/{taskId}/regenerate`

**干什么**：规则库改了、或想重写措辞时，丢掉旧报告重算。

```json
{
  "taskId": 6,
  "complianceRate": 0.987,
  "summaryText": "……",
  "regenerated": true
}
```

> 注意：重算只重新统计已落库的 `finding`，**不会重新调模型**。想重新判定就重新上传文件。

### 4.10 规则蒸馏 `POST /api/rules/distill`

**干什么**：A 通道。读一份规范文本（阿里手册、pylint 文档等），切块 → 逐块让模型抽规则 → 证据回查 → 去重 → 入库。

**请求**

```powershell
curl.exe -X POST "http://localhost:8080/api/rules/distill?docPath=docs-source/java/alibaba-p3c.txt&language=java&startChunk=210&maxChunks=15"
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `docPath` | 是 | — | 相对工程根目录的路径（`.txt/.md/.rst/.pdf`） |
| `language` | 是 | — | `java` / `python` |
| `startChunk` | 否 | 0 | 从第几块开始（0 起），用来跳过命名/格式章节 |
| `maxChunks` | 否 | 5 | 本次最多跑多少块（**每块一次模型调用**，别一次跑 300 块） |

**响应**

```json
{
  "doc": "alibaba-p3c.txt",
  "language": "java",
  "chunksTotal": 317,
  "chunksFrom": 210,
  "chunksProcessed": 15,
  "candidates": 29,
  "saved": 28,
  "droppedEvidence": 0,
  "droppedInvalid": 1,
  "droppedDuplicate": 0,
  "callFailed": 0,
  "byCategory": { "injection": 11, "auth": 6, "style": 7, "crypto": 1, "secrets": 1 },
  "byDetectability": { "semantic": 23, "manual": 5 },
  "savedIds": ["JAVA-DOC-302ae323", "JAVA-DOC-0eae97e8"]
}
```

这几个计数就是论文里的"规则抽取质量表"：

| 字段 | 含义 |
|---|---|
| `candidates` | 模型一共吐出多少条候选 |
| `droppedEvidence` | 证据回查失败（`evidence_quote` 不在原文里）→ 判为幻觉，丢弃 |
| `droppedInvalid` | 字段不合枚举（CWE 写法怪、severity 不认识）→ 丢弃 |
| `droppedDuplicate` | 同批次或与库内重复 → 丢弃 |
| `callFailed` | 模型调用失败次数（网络/额度） |

**失败边界**：文档不存在 → 500 带路径；切不出条款 → 退化为按段落切分并打警告日志。


```json
  "imported": 8,
  "skipped": 0,
```

## 5. 三条典型调用链

### 链 1：一次完整审计（前端主流程）

```
POST /api/upload            → taskId=6（同步等 14 秒）
GET  /api/audit/tasks/6     → status=DONE, violations=3
GET  /api/audit/tasks/6/findings  → 3 条明细（行 7 / 11 / 15）
GET  /api/report/6          → complianceRate=0.987 + markdown + html
GET  /api/report/6/html     → 浏览器直接看
```

### 链 2：第一次把规则库灌满（部署时做一次）

```
POST /api/rules/import?path=docs-source/python/python-rules.json      → 97 条
POST /api/rules/import?path=docs-source/java/spotbugs-rules.json      → 179 条
POST /api/rules/import?path=docs-source/java/manual-rules.json        → 8 条
POST /api/rules/distill?docPath=docs-source/java/alibaba-p3c.txt&language=java&startChunk=210&maxChunks=15  → 28 条
GET  /api/rules/stats                                                 → total=329
```

### 链 3：答辩演示（不依赖网络）

```
1) 提前跑一次 upload，把 finding / report 落库
2) 现场只演示 GET 接口（tasks / findings / report/html）
3) 万一要现场审计，用 .java 小文件（3 块以内，20 秒左右）
```

> 风险提示：`upload` 与 `distill` 都依赖云端大模型，**答辩现场断网就跑不动**。演示包里要备一段预录视频或提前落库的任务。

## 6. 数据模型（4 张表）

### `rule` 规则

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | 自增 |
| `rule_id` | varchar(64) UNIQUE | 业务主键，如 `JAVA-SB-SQL_...` / `PY-BANDIT-B608` / `JAVA-DOC-38b354db` |
| `language` | varchar(16) | `java` / `python` |
| `category` | varchar(64) | injection / secrets / crypto / auth / path-traversal / error-handling / config / logging / naming / style / deserialization |
| `cwe` | varchar(32) | `CWE-89` 这种；没有就 `CWE-000` |
| `title` / `description` | varchar(200) / TEXT | 规则名与说明 |
| `positive_example` / `negative_example` | TEXT | 正反例（给模型看，也进论文） |
| `severity` | varchar(16) | HIGH / MEDIUM / LOW / INFO |
| `detection_hint` | TEXT | 怎么找：关键词、行号特征、调用链特征 |
| `evidence_quote` | varchar(200) | A 通道专用：≤50 字原文摘录，用于回查防幻觉 |
| `source_doc` / `source_ref` | varchar(64) | 来源文档与条款号（如 `alibaba-p3c` / `1`） |
| `detectability` | varchar(16) | pattern / dataflow / semantic / manual |
| `canonical_key` | varchar(64) | 跨语言归键，索引 `idx_rule_canonical` |
| `created_at` | datetime | |

索引：`idx_rule_language`、`idx_rule_category`、`idx_rule_canonical`、`idx_rule_lang_cat(language,category)`。

### `audit_task` 审计任务

`id` / `file_name` / `language` / `status`(PENDING/RUNNING/DONE/FAILED) / `rule_version` / `total_chunks` / `done_chunks` / `error_msg` / `created_at` / `finished_at`

### `finding` 判定结果

`id` / `task_id` / `rule_id` / `file_path` / `start_line` / `end_line` / `code_snippet` / `violated` / `severity` / `reason` / `fix_suggestion` / `confidence`

### `report` 报告

`id` / `task_id` UNIQUE / `summary_text` / `compliance_rate` / `markdown`(MEDIUMTEXT) / `html`(MEDIUMTEXT) / `created_at`

## 7. 命令行快速自测（复制即可跑）

```powershell
# 0) 探活
curl.exe http://localhost:8080/api/ping

# 1) 造一个坏样例
@'
import subprocess
PASSWORD = "admin123"
def run(cmd):
    subprocess.call(cmd, shell=True)
'@ | Set-Content -Encoding UTF8 F:\毕业设计\demo_bad.py

# 2) 上传（记住返回的 taskId）
curl.exe -X POST -F "file=@F:\毕业设计\demo_bad.py" http://localhost:8080/api/upload

# 3) 查结果（把 9 换成你的 taskId）
curl.exe http://localhost:8080/api/audit/tasks/9
curl.exe http://localhost:8080/api/audit/tasks/9/findings

# 4) 出报告
curl.exe http://localhost:8080/api/report/9/markdown
start http://localhost:8080/api/report/9/html
```

## 8. 常见错误对照表

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| `400 只支持 .java 和 .py 文件` | 传了 `.txt/.zip` | 换文件；需要支持更多语言要改 `FileUtil.detectLanguage` 与切片器 |
| `400 文件为空` | 0 字节 | 检查上传路径 |
| `400 任务不存在：N` | taskId 拼错或库被清过 | 先 `GET /api/audit/tasks` 拿真实 id |
| `413 文件超过大小限制（10MB）` | 超 multipart 上限 | 调 `application.yaml` 的 `max-file-size` |
| `500 未配置 LLM_API_KEY` | 没设环境变量 | IDEA 运行配置里加 `LLM_API_KEY=sk-...` |
| `500 模型不存在的 404` | `llm.model` 写了显示名 | 用 `/v1/models` 列出的真实 id（如 `deepseek-v4.1-flash`） |
| 前端报 CORS | 端口不同且没走代理 | 已配 `WebConfig`；确认请求的是 `http://localhost:8080/api/...` |
| 上传一直转圈 | 审计同步执行，块多就慢 | 前端 timeout ≥120s；大文件拆小再传 |

## 10. 前端接入包（可直接抄）

这一节是给"明天开始写 Vue 的人"用的：一个 `api.js` 覆盖全部 13 个接口，外加四个页面的数据流。

### 10.1 `src/api.js`（axios 封装）

```javascript
import axios from 'axios'

// 开发期走 Vite 代理（vite.config.js 里 '/api' -> http://localhost:8080），
// 这样浏览器看到的是同源请求，连 CORS 都不用管。
const http = axios.create({
  baseURL: '/api',
  timeout: 120000,           // 上传接口是同步审计，短了会假超时
})

// 统一错误：后端出错时返回 {timestamp,status,error}
http.interceptors.response.use(
  (resp) => resp.data,
  (err) => {
    const msg = err.response?.data?.error
      || (err.code === 'ECONNABORTED' ? '审计超时：文件太大或模型太慢，请拆小再试' : err.message)
    return Promise.reject(new Error(msg))
  },
)

export default {
  // 探活
  ping: () => http.get('/ping'),

  // 上传并审计（同步，返回 taskId）
  upload: (file, onProgress) => {
    const form = new FormData()
    form.append('file', file)
    return http.post('/upload', form, {
      headers: { 'Content-Type': 'multipart/form-data' },
      onUploadProgress: (e) => onProgress?.(Math.round((e.loaded / e.total) * 100)),
    })
  },

  // 任务
  tasks: () => http.get('/audit/tasks'),
  task: (id) => http.get(`/audit/tasks/${id}`),
  findings: (id) => http.get(`/audit/tasks/${id}/findings`),

  // 报告
  report: (id) => http.get(`/report/${id}`),
  reportMarkdown: (id) => http.get(`/report/${id}/markdown`),   // 返回字符串
  reportHtml: (id) => http.get(`/report/${id}/html`),           // 返回字符串
  regenerate: (id) => http.post(`/report/${id}/regenerate`),

  // 规则库
  rules: (language, limit = 20) => http.get('/rules', { params: { language, limit } }),
  ruleStats: () => http.get('/rules/stats'),
  importRules: (path) => http.post('/rules/import', null, { params: { path } }),
  distill: (docPath, language, startChunk = 0, maxChunks = 5) =>
    http.post('/rules/distill', null, { params: { docPath, language, startChunk, maxChunks } }),
}
```

> 如果不用 Vite 代理、直接打 `http://localhost:8080/api`，把 `baseURL` 换掉即可——后端 CORS 已经放开。

### 10.2 四个页面的数据流

**① 上传配置页**

```
选文件 → 本地校验后缀(.java/.py)与大小(≤10MB)
      → api.upload(file, p => 进度条 = p)
      → 成功拿到 {taskId, language, savedAs}
      → 表单一侧显示"共 N 块、语言 java"，按钮变"查看报告"跳转 ②/③
```

注意：进度条只反映**上传字节数**，到 100% 之后还要等审计（十几秒），这期间必须显示"正在审计…"的 loading，不能直接跳走。

**② 任务列表页**

```
onMounted → api.tasks() → 表格（文件名 / 语言 / 状态 / 违规数 / 时间）
点某行 → router.push(`/report/${row.id}`)
有 RUNNING 的任务时：setInterval 3 秒调 api.task(id) 刷新进度（doneChunks/totalChunks）
```

**③ 报告页**

```
api.findings(id) → 明细列表（按 startLine 升序）
api.report(id)   → 顶部卡片：合规率(= complianceRate*100 保留1位)、结论句(summaryText)
                  → 代码区：按 codeSnippet 首行对应到 startLine 高亮
                  → 图表：severity 计数饼图 + 每条规则的命中条数柱状图（ECharts）
下载按钮 → window.open(`/api/report/${id}/markdown`)
投屏按钮 → window.open(`/api/report/${id}/html`)
```

代码高亮的最小做法（不引整个编辑器）：

```javascript
// 用 highlight.js 把 snippet 染色，行号自己排
import hljs from 'highlight.js/lib/core'
import java from 'highlight.js/lib/languages/java'
import python from 'highlight.js/lib/languages/python'
hljs.registerLanguage('java', java)
hljs.registerLanguage('python', python)

const html = hljs.highlight(finding.codeSnippet, { language: job.language }).value
// 模板里显示：第 {finding.startLine} 行
```

**④ 规则库浏览页**

```
api.ruleStats() → 顶部四个数字：总数 / 分语言 / 分类分布（柱状图）/ 跨语言组数
api.rules(language, 20) → 表格（ruleId / 标题 / 分类 / CWE / 等级 / 来源）
点某行 → 抽屉里显示 description / detectionHint / 正反例 / evidence_quote
```

### 10.3 展示约定（别自己发明）

| 字段 | 规则 |
|---|---|
| `severity` | HIGH → `#f56c6c`，MEDIUM → `#e6a23c`，LOW → `#909399`，INFO → `#409eff` |
| `confidence` | 显示百分比（0.95 → 95%）；**< 0.5 加"待人工确认"角标**，这是块 5 设计里的降权档位 |
| `status` | PENDING 灰、RUNNING 蓝（带 loading）、DONE 绿、FAILED 红 |
| 行号 | `startLine` 与 `endLine` 相同就显示"第 N 行"，不同显示"第 N–M 行" |
| 时间 | 后端给的是 ISO 字符串，直接 `dayjs(v).format('MM-DD HH:mm')` |

### 10.5 联调顺序（建议）

1. `ping` 连通 → 顶部状态灯绿；
2. `upload` 一个真文件 → 拿到 taskId（先不管页面好看不好看）；
3. `tasks` + `task` 把列表与进度画出来；
4. `findings` 画明细；
5. `report` 接合规率与结论，`/html` 做"投屏"按钮；
6. 最后才接规则库两个接口（答辩演示权重低）。

# 实现分块 · 施工图（人和 AI 共用）

这个目录不是"文档"，是**施工单**。6 个文件对应后端的 6 个块，一块一验收。

---

## 给 AI 的指令（复制粘贴到 Trae / Continue 的对话框）

```
你是这个项目的实现工程师。项目根目录是 F:\毕业设计\graduation-audit。

本次只实现一个块：docs/实现分块/块1-基础链路.md

规则：
1. 先完整读这个文件，再动手；不要读其他块的文件，也不要一次实现多块。
2. 严格按文件里的「操作步骤」编号顺序写代码：类名、包名、字段名、方法签名一致。
3. 不要新增 Maven 依赖（文件里明确要求加的除外），不要改 pom 里的 Java 版本。
4. 不要顺手"优化"其他类；只改本文件「涉及文件」表里列出的文件。
5. 写完后，逐条对照文件末尾的「验收」清单，把每条的实际结果（通过/未通过 + 证据，如返回的 JSON、SQL 查询结果）列出来。
6. 如果有哪一步你判断做不到或环境不支持，直接说，不要绕过。

现在开始，第一步先告诉我你会改哪几个文件。
```

把 `块1` 换成当前要做的块即可。**做一块换一块**，不要一次贴 6 个。

## 每个文件里都有这 7 段

1. 目标 / 前置 / 产出 / 估时 / **验收标准（不达标别往下走）**
2. 这一步在回答什么问题（为什么现在做）
3. 涉及文件表
4. 操作步骤（带完整可粘贴的代码）
5. 验收清单（`- [ ]`）
6. 卡住怎么办（现象 → 原因 → 修法）
7. 做完记录（往 `docs/03-实现过程记录.md` 哪一栏写什么）
